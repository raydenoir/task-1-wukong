# WukongRunner

Инструмент на C# / .NET 10 для автоматического запуска Steam релиза
Black Myth: Wukong Benchmark Tool. Автоматически делает CPU- и GPU-проход,
меняет настройки через INI и читает результаты из JSON репорта самой игры, форматируя их в report.txt

## Запуск

Сделано под Windows.
Нужны установленный Benchmark Tool и Steam с выполненным входом в аккаунт.
Предварительно запускать Benchmark Tool и настраивать его вручную не требуется.

Для готового релиза скачайте EXE и INI в одну папку.
Запуск:

```powershell
.\WukongRunner.exe
```

Из папки исходников, с установленным .NET 10 SDK:

```powershell
dotnet run
```

Папка игры находится в реестре Windows `Steam App 3132990`, поле `InstallLocation`.
Если записи нет или путь неверный, можно передать папку вручную:

```powershell
.\WukongRunner.exe "D:\SteamLibrary\steamapps\common\Black Myth Wukong Benchmark Tool"
```

Для исходников: `dotnet run -- "папка установки"`.
Во время проходов не меняйте настройки, не останавливайте сцену и не закрывайте игру.
Отмена - Ctrl+C, таймаут - 5 минут на профиль, включая запуск и загрузку.
`report.txt` сохраняется в текущей папке, после каждого прохода.
Исходный конфиг возвращаем при завершении, ошибке или Ctrl+C.
Если его не было, удаляем временный INI, а другие созданные игрой файлы остаются.

## Сборка

```powershell
dotnet build -c Release
dotnet publish -c Release -r win-x64 --self-contained true `
    -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
    -p:DebugType=None -o dist/app
```

Готовые EXE и шаблон будут в `dist/app`.
`GameUserSettings.template.ini` должен находиться рядом с программой;
при сборке и публикации он копируется автоматически.

## GitHub Release

```text
WukongRunner.exe
GameUserSettings.template.ini
```

Скачайте оба файла в одну папку и запустите EXE.

## Настройки двух проходов

| Параметр         | CPU       | GPU                         |
| ---------------- | --------- | --------------------------- |
| Разрешение окна  | 1280×720  | Разрешение основного экрана |
| Масштаб (запрос) | 25%       | 100%                        |
| Качество графики | Low       | Cinematic                   |
| Дальность        | Cinematic | Cinematic                   |
| Full Ray Tracing | Выкл.     | Максимум, уровень 3         |
| Motion Blur      | Выкл.     | Strong                      |

Качество графики включает сглаживание, постэффекты, тени, текстуры, эффекты,
волосы, растительность, освещение и отражения, у всех один уровень из профиля.

В обоих проходах используется TSR, выключены генерацию кадров, VSync,
динамический масштаб и лимит FPS. VSync и лимит FPS могли бы ограничивать
производительность, генерация кадров меняет измеряемый режим, а динамический
масштаб менял бы разрешение во время сцены.

В CPU-профиле низкое разрешение, Low пресет и выключенные Motion Blur и трассировка уменьшают работу GPU.
Запрашиваем масштаб 25%, дальность Cinematic сохраняет работу подготовки сцены на CPU.
Окна 960х540 и 640х360 применялись, но в репорте игры указывалось 1280х720.
Устойчивого выигрыша они не показали, потому оставил 1280х720.

GPU-профиль увеличивает работу видеокарты за счет
полного рендера, максимального качества, Motion Blur на Strong и трассировки, разрешение берется у основного
экрана через Windows API.
Максимальное качество задается при 100% масштабе и разрешении основного экрана.
Дальность Cinematic оставляем, чтобы не уменьшать сложность сцены.
Пытаемся запросить RT уровня 3, не проверялось на видеокарте без поддержки RT.

Изоляция зависит от ПК, для CPU-прохода ожидаем время CPU больше времени GPU,
и наоборот для GPU-прохода.
Среднее время на кадр считается по `Records.CPUFrameTime` и `Records.GPUFrameTime`
из JSON, FPS берется из готовых итоговых полей игры.

## Проверка

Пример результатов на i7-10750H, RTX 2060 6 GB,
32 GB RAM, экран 1920×1080:

| Проход | Средний FPS | CPU, мс/кадр | GPU, мс/кадр |
| ------ | ----------: | -----------: | -----------: |
| CPU    |          90 |        11,12 |         7,98 |
| GPU    |          16 |        10,47 |        61,08 |

В GPU-проходе загрузка видеокарты составила 99% по данным игры,
время GPU примерно в шесть раз выше времени CPU. На тестовом ПК
это подтверждает высокую нагрузку на GPU и ожидаемое ограничение с ее стороны.

Дополнительно сделал 10 CPU-прогонов с разными масштабами и размерами окна.
Ниже повторные проходы 1280х720 при одинаковых остальных настройках:
| Масштаб (запрос) | Средний FPS | CPU, мс/кадр | GPU, мс/кадр |
| ---------------- | ----------: | -----------: | -----------: |
| 25% | 96-97 | 10,33-10,38 | 7,05-7,30 |
| 50% | 96-99 | 10,16-10,50 | 6,55-7,29 |
| 100% | 68-69 | 10,05-10,23 | 13,12-13,46 |

При низком масштабе время GPU уменьшилось примерно с 13 до 7 мс,
время CPU осталось около 10 мс, что согласуется с переходом от ограничения
по GPU к ограничению по CPU (на проверенном ПК).

При запросе 25% JSON сообщает 25%, но игра сохраняет `sg.ResolutionQuality=50`,
как и при запросе 50%. Преимущества 25% перед 50% не подтвердилось,
а значение из репорта игры не доказывает точный размер внутренних буферов рендера.
В финальном профиле было решено оставить запрос 25%, поскольку при проверке 33% расчет размеров давал 32% в репорте игры,
а проверенные меньшие разрешения не показали заметного улучшения.
